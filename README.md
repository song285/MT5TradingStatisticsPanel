# 账户交易统计面板 v2.30（DPI 与窗口自适应版）

`MT5交易盈亏统计面板（高性能版）.mq5` 是 MT5 图表窗口指标，不会下单、修改持仓或写入账户历史。复制它及 `Include/AccountStatsData.mqh`、`Include/AccountStatsUI.mqh`，保持相对目录后编译；已编译文件是 `MT5交易盈亏统计面板（高性能版）.ex5`。

## 表格内容

每日、每周、每月、每年页签显示筛选范围内的每一个周期一行，倒序排列，并在底部显示“合计（全部筛选范围）”。每行包含：手数、最小/最大手数、订单次数、盈亏金额、盈亏百分比、入金、出金、期末余额、最大浮亏及比例、最大浮盈及比例。上方余额曲线按当前页签的周期绘制。

默认范围是账户当前可用的全部历史。也可以在面板输入 `YYYY.MM.DD` 的起止日期后点“应用”；留空表示不限制。`全部` 恢复全部历史。没有成交、出入金或浮盈亏采样的周期默认隐藏，输入参数 `ShowEmptyPeriods=true` 后会显示完整日历周期。周期按服务器日期计算，周一至周日为一周；起止日均包含。

表格按面板可用宽度显示完整列，列太多时用底部的“列 >”和“< 列”查看右侧浮盈亏列；周期较多时用首页、上一页、下一页、末页翻页。所有页签的合计不随当前页或当前可见列改变。

## 窗口操作

标题栏按住鼠标左键移动面板。`-` 收起为标题栏，`+` 恢复到首选宽高；面板已经展开时点 `+` 不改变尺寸。`R` 重新核对账户历史。`+` 没有铺满图表的最大化操作。

默认首选尺寸为 `PanelWidth=1060`、`PanelHeight=640`，单位为 96 DPI 的逻辑像素。每页最多 `RowsPerPage=11` 条，可在指标参数中设置为 1-12。空间充足时按首选尺寸显示；图表较小时，缩小至可用区域，不再让表格和底部按钮超出图表。

### 分辨率与 Windows 显示缩放

旧版将文字字号与控件像素尺寸分别设置，遇到高 DPI 显示缩放时，字体可能放大而行高与列宽不变，形成截图中的重叠。v2.30 读取 `TERMINAL_SCREEN_DPI`，对坐标、控件、字体、曲线位图和拖动命中区域使用统一换算，同时依据图表的实际像素宽高重新排版。调整图表尺寸时立即更新，每秒还会检查一次 DPI 是否变化。

- 空间变小时自动减少每页行数，页数和按钮可用状态随之更新；原本所在页的记录位置会尽量保留。
- 窄面板将数据翻页与列翻页放在两行；窄表格固定保留日期列，再显示能完整容纳的数据列，其余指标用列按钮查看。
- 低高度图表会缩短或隐藏余额曲线，优先保留表格、合计及翻页按钮。
- 账户页也会按高度分页，全部 16 项信息均可通过上一页、下一页查看。
- 过长的标签和数值按实际字体宽度显示省略号，悬停可查看完整值。字体测量结果缓存，数据与布局均未变化时不重复测量。
- 小于约 270×200 像素的图表仅显示标题栏与增大图表提示，恢复空间后自动展开内容；这种窗口无法同时容纳完整的筛选、表格和分页控件。

无需为了面板修改电脑的系统分辨率或强制将 Windows 缩放设为 100%。DPI 信息由终端提供；离线测试不代替具体 MT5 版本和多显示器设置下的实测。

表格末尾不足一页的占位行会显示 `-`，不会显示旧的 `Label`。页码旁会显示周期数和当前实际每页条数；例如 9 个周期、可容纳每页 11 条时显示 1 / 1 页，这是因为数据确实只有一页。把 `RowsPerPage` 改成 5，或把日期范围扩大到超过每页条数后，下一页和末页按钮就会启用。

## 统计口径

- 首次加载、手动 R 和默认每 60 分钟做一次完整历史核对。平时只重读上次快照日期前一天至现在的近期窗口，并替换这些日期的账本，避免同秒成交、延迟入账或重复刷新被漏计/重计。较早日期的修正由完整核对处理。
- 手数为买卖成交量之和。盈亏包含 profit、swap、commission 和 fee，并纳入独立佣金、利息、股息、税费及更正类记录。信用额不计入余额。
- 订单次数及最小/最大手数来自已完成的历史订单，按订单执行日期归入周期。
- 入金/出金来自 `DEAL_TYPE_BALANCE` 的正负金额。百分比按该行期初余额加本行入金重新计算，不把各行百分比相加。
- 期末余额由账户历史现金流逐日累积，避免每一行误用当前余额。
- 最大浮亏/浮盈通过定时器采样 `净值 - 余额 - 信用额`。MT5 历史不能恢复挂载前的浮动盈亏，因此未采样的值显示 `--`；采样记录按账户和服务器保存到 `Files/AccountStatsPanel`，终端重启后继续使用。

## 性能与验证

这次优化处理了历史枚举占用事件线程、同步图表查询和全表重复绘制三个瓶颈：

- **分批读取历史**：50 毫秒定时器只在有任务时处理一小批。默认每批预算 `HistorySliceMs=8` 毫秒，另设最多 2000 条的硬上限；每个批次返回后让出事件线程。历史快照在独立日账本中构建，完成后一次提交，核对期间仍可查看和翻动上次完整结果。首次加载可能需要等待，页脚显示读取进度。
- **切页不查历史**：日、周、月、年四组统计分别缓存；翻页只读取当前页至多 12 行，切换统计页签直接使用缓存。余额曲线复用位图并按像素宽度抽样，不按每笔成交创建图表对象。
- **只更新变化属性**：本地记录对象和属性，渲染路径不再逐单元格调用同步 `ObjectFind`。切换统计页签复用同名表格对象；无变化时不写属性、不强制重绘。账户页最多每秒更新一次，浮盈亏新峰值直接更新对应周期及合计。
- **内存有界**：只保留按日账本、按周期结果、当前页对象和一份临时读取账本。每次重建替换缓存，注册表固定上限，历史原始成交不另存一份。

压力场景使用 **100 万条成交 + 100 万条订单**，分 1000 批完成读取；800 次缓存切页/翻页没有调用历史 API、没有创建新表格对象、没有调用同步 ObjectFind；连续 1000 次无变化渲染写入 0 个图表属性；重复重建后缓存数量保持不变。测试以 C++ 编译提取的实际 MQ5 函数，图表/账户/历史 API 使用模拟实现，耗时不能视为实际 MT5 的性能保证，也未连接真实交易账户。

窗口布局另外覆盖 10 种图表大小（3840×2160、2560×1440、1920×1080、1366×768、1280×720、1024×768、800×600、600×400、360×330、240×160）与 5 种 DPI（96、120、144、192、288，即 100%、125%、150%、200%、300%），共 50 组组合，遍历全部 5 个页签。检查控件与模拟文字边界、合计与分页位置、所有数据列和账户字段可达性、DPI 切换、200% 缩放拖动、最小化恢复；调整布局不会重新读取历史。图表 API 和字体测量使用模拟实现，布局预览由生产代码输出的坐标生成，并非实际 MT5 截图。
